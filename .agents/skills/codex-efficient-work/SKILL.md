# Codex Efficient Work

Control context cost while preserving project validation and authorization.
This skill does not grant commit, deployment, data-mutation or delegation authority.
Detailed resource ledgers are optional project policy, not a default requirement.

## Select the task

- **Optimize or prepare:** follow the guidance below and any supplied project
  profile. For transfer, adapt [assets/project-profile.example.md](assets/project-profile.example.md)
  from destination rules; do not copy this repo's models, commands or budget.
- **Explicit allowance budget:** also read
  [references/measurement.md](references/measurement.md#allowance-budget).
  Enable quota stops only when requested; preserve the saved startup baseline.
- **Completed-session audit:** read
  [references/measurement.md](references/measurement.md#session-audit).
  Read logs only; never resume or contact audited sessions or agents.
- **Suspected defect or interrupted work:** use
  [references/defect-recovery.md](references/defect-recovery.md) to preserve the
  finding, validate a defensive fix and continue permitted independent work.

## Bound context and coordination

Start from the current checkpoint, contract and relevant source. Prefer final
closeout facts; load history only as needed. Inspect scorecard rows, failure
diagnostics and fixture keys, counts and hashes, not full histories or JSON.
Keep full outputs in artifacts. Use short result/blocker updates with links;
preserve precision.
Keep implementation checkpoints separate from token audits and run preparation.
If the user requests an audit during implementation, honor it and account for
that phase separately; do not add audits to routine implementation closeout.

Use one implementer for serial work. Delegate only with authorization and an
independent scope. State objective, base, paths, invariants, checks, exclusions
and report format. Confirm actual model routing. Reuse agents within settled
scopes; use fresh review context at meaningful profile changes. Avoid duplicate
leads and routine polling. Tie each assignment to a named acceptance gap and
consumer. Return evidence, changes and blocker; do not expand a bounded map into
an inventory. Repeat an unavailable-input probe only when evidence changes its
inputs or resolves the failure condition.

When a bounded task repeats the same semantic profile family, read
[references/repeated-families.md](references/repeated-families.md). Do not use
this procedure for ordinary coding or to skip a required review.

When evidence or history growth obstructs review, read
[references/evidence-records.md](references/evidence-records.md).

Check capacity before spawning. If required fresh review cannot start, checkpoint
before dependent work. Distinguish listed status, observed spawn rejection and
model/account limits. Do not retry unchanged failures or silently substitute models.
A capacity stop does not authorize moving or resetting a session-bound budget.

## Preserve acceptance

Run the smallest required checks first and require nonzero matched tests. Save
complete outputs/exits and first failures; repeat for changed inputs, failures or
named unresolved concerns. Inspect actual APIs and constructors before copying
tests. Check request bindings and fixture assumptions before
expensive gates. Reuse evidence only for exact unchanged hashes and covered scope.

Request independent final review after required checks and freeze. An early bounded
source pass can finish separately with one later evidence handoff. Selected values
do not prove complete database preservation. Reuse tested observation helpers when
repeated corrections expose a missing invariant. Correct findings and revalidate
affected behavior. Cost savings never waive checks or widen acceptance claims.

Continue ready authorized work within scope and stopping conditions. A checkpoint
records accepted base, pending paths/hashes, checks/review, blockers and next action.
Replace stale facts; link history. At a quota limit stop new work and save a durable
handoff. Finishing a slice or resuming does not create a new allowance budget.
Before proposing more quota, distinguish quota, telemetry, project-resource and
implementation blockers; more allowance does not resolve every stop.

## Evaluate and transfer

Compare accepted behavior, corrections, elapsed time and review quality. Commits
are weak task proxies. Keep tokens, dated cost estimates and allowance separate.
Cached input costs money; short replies alone may not fix repeated large context.
Measure routing/context changes before claiming equivalent-task savings.

Copy this directory and provide a destination project profile. Its Python quota
helper and tests are self-contained; verify local log schema/account compatibility.
