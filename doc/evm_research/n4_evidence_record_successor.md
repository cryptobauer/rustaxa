# Proposed bounded evidence-record successor

Status: preparation proposal only. No contract amendment, source acceptance,
command READY or physical execution is granted here. New-run authority review
must settle exact input/role/path lists, composition, bounds and successor mapping.

## Problem

Residual command/outcome records already reach399–400 charged occurrences.
Review/code records below128KiB are also required to contain whole historical
failure bodies. Later corrections add more bodies and representation decisions.
The pending45-profile has passed source gates but final acceptance is blocked by
record assembly. These are record-format constraints, distinct from the13
physical witness ceilings and proof/retention invariants.

## Proposed record shape

Retain each complete original failure/gate/review artifact immutably. A current
review note states objective/base, invariant, exact finding, correction, current
status and applicable final check. Its evidence entries contain role, canonical
fixed path, size and digest. Do not place complete old logs or reviews inside
new prose. Logs are not deleted or replaced by a success boolean.

Separate three ledgers:
- Execution authority: exact source/binary/request/command/output pins and required
  proof/prior/retention inputs. Preserve fail-closed guards and consumed markers.
- Validation: full gate outputs/exits, test selectors/counts, corrections and review.
- Provenance: immutable older acceptance and failure records, with explicit successor
  mappings. A provenance digest is not a native/state proof.

Define finite ordered lists and an explicit trust boundary for each. No arbitrary
embedded paths or generic recursive ancestry traversal. Authenticate every named
required body, including byte size and full digest, before using its reference.
A tested bounded verifier streams fixed files; it rejects changed/missing bodies,
role/identity mismatch, duplicate conflicts, unconsumed entries and cap overflow.
Use existing per-record bounds where applicable. Set exact list/count/read-byte/
allocation/source/output limits in the reviewed implementation contract; this
proposal supplies no unrestricted new allowance or silent cap increase.

## Required authority decision

Inventory the exact inherited233 and current source/command/outcome roles once.
Classify which are physical authority and which are validation/provenance.
Name every predecessor and replacement representation; preserve order/multiplicity
where semantically required. Show old/new counted occurrences and actual read/byte
charges. Hashing duplicate bytes once does not by itself waive a charged role.
Astra must explicitly accept any changed representation/charging; Sol independently
checks mapping, implementation, exact command and final proof results.

All old freezes, full logs, archives and outcomes stay immutable. A successor may
verify archived old source pins and authorized current source separately; it may
not retarget historical pins. Existing embedded-body contracts remain enforceable
until the exact named successor is accepted. Pending45 source and command require
fresh acceptance under either the current contract or that accepted successor.

## Validation before use

Prove complete original failure bodies remain retrievable and hash-valid. Test
same-size drift, wrong role/path, missing body, duplicate/conflict, count/byte/cap+1,
path aliases, output collision and failure without acceptance. Compare mandatory
input coverage and proof outcomes with current accepted records offline. No live
DB reads are needed to design or test this record change. All physical read/proof,
single-use, deadline and independent replay checks stay unchanged.

This is a narrow tooling/schema change, not a rewrite of historical acceptance or
an authorization to construct a writable owner. Prefer solving it once over another
profile-specific body-packing exception. If representation cannot be justified,
record the precise blocker rather than repeatedly attempting the same assembly.
